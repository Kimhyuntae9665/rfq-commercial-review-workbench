# UI contract and verification

Task-first Korean RFQ workbench with system fonts and a 14px minimum body/table/evidence font. The desktop has RFQ quantity and date inputs on the left, three offers and a normalized comparison table in the center, and unresolved conditions, packet acknowledgement, and audit history on the right. Narrow screens stack the panels; tables scroll inside their containers.

The extraction selector defaults to baseline rules. Users may explicitly choose the existing 4B model on localhost; offers are processed sequentially with per-offer progress, and the selector stays disabled until the operation completes. The model extracts only and never computes quantities, prices, dates, or supplier selection. Each proposal card identifies baseline extraction, an actual model result with server-verified source quotes, or model failure followed by rule fallback and required direct confirmation. Every current proposal opens a separate native dialog containing all 17 fields, full original-cell quotes, source hash/revision and original document. Selecting a quote highlights its server-provided Unicode code-point span using `Array.from`; it checks exact quote equality before rendering the highlight. The human must acknowledge the original quotes before the confirmation POST. A failed-model proposal requires an additional manual-confirmation checkbox. New extraction invalidates the visible packet and needs fresh confirmation.

The deterministic calculation button stays disabled until all three current proposals are confirmed. Quantity is a positive safe integer no larger than 1e12. Costs and normalized quantities render only from server `exact_values` decimal strings, grouped by a regex without converting them to JavaScript Number. The backend cost order applies only to complete comparable offers, with visible completeness (2/3 in the fixture). Unknown freight never becomes zero; delivery conditions are separate from comparison eligibility. Evidence values use the original `fields.raw_value` strings.

Changing the local quantity or date immediately hides prior calculation numbers, packet review, and final acknowledgement controls. Recalculation creates a new packet. Reviewer identity uses a new ephemeral bearer session and re-fetches the previously viewed packet under the new principal. Buyer identity cannot record packet review. The reviewer separately acknowledges comparison scope and unresolved conditions before recording `reviewed` or `needs_followup` with the expected fingerprint. The UI clearly labels both identities as synthetic demo profiles, not actual SSO. Nothing selects a supplier, accepts a legal quotation, approves a purchase, or issues an order.

The API receives credentials only in the Authorization header. DOM text is escaped or inserted with textContent; no bearer or private path is rendered. Source/evidence reads always use the server; errors and stale conflicts are shown in a live status region. No external library, font download, or browser launch is used. The browser verification script uses the default baseline option and makes zero model requests; selecting the model in the UI is a distinct explicit action.

Run `python3 scripts/browser_check.py` after the server is listening at loopback port 19083 and the existing sandboxed Chrome CDP endpoint is available at 19085. The stdlib CDP driver creates/closes its own tab and produces actual screenshots and a machine-readable result in `artifacts/browser/`. It verifies both human gates, the 12-to-30 cost-order reversal within 2/3 complete offers, unknown freight, exact costs, scenario invalidation, reviewer access, source-span equality, source-trigger focus restoration, minimum font size, computed text contrast, calendar dates under America/Los_Angeles, desktop/mobile/200% zoom-equivalent reflow, the baseline-default selector, its busy lock, per-offer progress, and explicit extraction-origin labels. Unsupported HTML-like units, large integer strings above 2^53, and long Korean conditions are temporary browser display-boundary regressions that are restored before screenshots; they do not modify the corpus or represent real model outputs. It never imports evaluator gold or calls the model.

Previous recorded run: 47 checks passed, seven actual UI screenshots, zero model requests, minimum checked visible task text contrast 4.563, and a 14px minimum task/table/evidence font. `artifacts/browser/checks.json` includes screenshot hashes and exact check labels. The 200% case uses a 720 CSS-pixel viewport with deviceScaleFactor 2; it is labeled as zoom-equivalent reflow, not a recording of browser menu zoom. Demand-30, source-confirmation and mobile screenshots were transferred and visually inspected. No supplier columns move when the cost order changes.


## Evidence dialog accessibility and local errors

The native evidence dialog is named by evidence-title through aria-labelledby. While it is open, source validation or confirmation-request errors are mirrored into an assertive, atomic alert inside the dialog with textContent, and the alert scrolls into the viewport without moving keyboard focus. The background status remains available after closing. The local alert clears on a new dialog task, a valid source highlight, closing, and reopening; a failed confirmation keeps the dialog open and does not invent a confirmation. Source hash, ACL, extraction verification and review rules remain unchanged.

The affected actual baseline browser run passed 56 checks and the existing engineering suite passed 69/69 in 16.308 seconds. New checks cover native accessibility-tree dialog naming, keyboard focus staying inside the modal, a visible/accessibility-tree alert for an explicitly mocked invalid span, clearing after a valid quote, and a mocked HTTP503 confirmation error with HTML-like text rendered literally. The confirmation HTTP fault intercepts before sending the POST; it is a UI regression fixture, not a server incident or model result. Close/reopen cleanup is checked after the native asynchronous close event. Model requests are zero. Existing docs/demo images, video and Library uploads are unchanged; browser test artifacts remain transient in artifacts/browser/. This targeted modal check does not claim a complete screen-reader audit.
